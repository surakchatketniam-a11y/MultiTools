# กติกาการพัฒนาเครื่องคำนวณ

กติกานี้ใช้กับทุกไฟล์ใต้ `calculator_AIO/` สำหรับการเพิ่มหรือแก้เครื่องมือ รวมถึงงานที่ทำโดย Gemini และเอเจนต์อื่น อ่านก่อนเริ่มงาน และยึดคำสั่งล่าสุดของผู้ใช้เป็นหลัก

## อ่านก่อนเขียนโค้ด

- อ่านระบบธีมและส่วนประกอบกลางใน `index.html` และ `src/ui/theme.js`
- ดู `renderSalaryTool` ใน `src/tools/biz.js` และเครื่องมือใน `src/tools/finance_thai.js` เป็นตัวอย่าง
- อ่าน `src/ui/keypad.js` ก่อนเชื่อมช่องกรอกกับคีย์แพดกลาง
- ตรวจไฟล์ที่มีการแก้ค้างอยู่ ห้ามเขียนทับหรือลบงานของผู้ใช้

## ใช้ส่วนประกอบกลาง

| หน้าที่ | คลาสที่ใช้ |
| --- | --- |
| การ์ดกรอกข้อมูล | `themed-tool-card` |
| การ์ดผลลัพธ์ | `themed-result-card` |
| ตัวเลขผลลัพธ์สำคัญ | `themed-result-value` |
| ส่วนย่อยภายในการ์ด | `themed-subcard` |
| ตัวเลือกโหมด | `segment-group` และ `segment-btn` |
| ช่องกรอกและ select | `airbnb-input` |
| ปุ่มทำงาน | `tool-action-btn` |
| ปุ่มข้อความ | `tool-text-btn` |
| ปุ่มค่าลัดหรือตัวเลือกย่อย | `tool-chip-btn` |
| ปุ่มลบ | `tool-danger-btn` |

ใช้คลาสเหล่านี้โดยตรง อย่าสร้างหน้าตาปุ่ม การ์ด และช่องกรอกใหม่ขึ้นมาแทน หากส่วนประกอบเดิมไม่รองรับ ให้ตรวจรูปแบบที่เครื่องมืออื่นใช้ก่อน และอธิบายส่วนที่ขาดก่อนเพิ่มรูปแบบใหม่

## สีและธีม

- ใช้ตัวแปรกลาง: `--app-ink`, `--app-body`, `--app-muted`, `--app-hairline`, `--app-accent`, `--app-accent-active`, `--app-accent-soft`, `--app-surface-soft` และ `--app-surface-strong`
- ใช้รัศมี ฟอนต์ และเงาจากระบบกลาง เช่น `--app-card-radius`, `--app-btn-radius` และ `--app-elevation`
- แอปใช้ `html[data-theme]` ไม่ใช่คลาส `.dark` จึงห้ามใช้ `dark:` เพื่อรองรับธีม
- ห้ามกำหนดสีพื้นผิว ข้อความ ปุ่ม และผลลัพธ์ตายตัว เช่น `bg-white`, `text-gray-*`, สี HEX หรือ RGB ในเครื่องมือใหม่ ให้ใช้ส่วนประกอบและตัวแปรกลาง
- สีสถานะสำเร็จ ผิดพลาด และคำเตือนให้ใช้รูปแบบกลางที่มีอยู่ พร้อมข้อความบอกสถานะ ไม่สร้างชุดสีเฉพาะเครื่องมือ
- อย่าใช้ `--app-header-bg` เป็นพื้นการ์ดทุกธีม: Classic และ Together มีส่วนหัวสีเข้มแต่เนื้อหาสีอ่อน
- ตรวจสีตัวอักษรบนปุ่มหลักด้วย โดยเฉพาะ Dark Luxe ที่สี accent เป็นสีอ่อน ใช้แนวทางของส่วนประกอบกลางและ `--app-on-accent` เมื่อมี
- ห้ามใส่อีโมจิหรือไอคอนตกแต่งนำหน้าหัวข้อ ป้ายช่องกรอก ข้อความช่วย และข้อความปุ่มในเครื่องมือใหม่ ส่วนควบคุมกลางเดิมให้คงไว้ เว้นแต่ผู้ใช้สั่งแก้

## การจัดหน้าและการเข้าถึง

- CSS เฉพาะเครื่องมือต้องครอบด้วยคลาสของเครื่องมือนั้น ห้ามแก้ selector กว้างจนกระทบเครื่องมืออื่น
- คำนึงถึงความกว้างของพื้นที่เครื่องมือจริง: บนเดสก์ท็อปตัวเครื่องคำนวณยังมีความกว้างจำกัด ใช้ container query หรือจัดคอลัมน์ตามพื้นที่จริงเมื่อจำเป็น
- ตรวจมือถือกว้าง 320px ห้ามข้อความ ตัวเลข ช่องกรอก หรือปุ่มล้นแนวนอนหรือทับกัน
- ให้ข้อความและยอดเงินยาวขึ้นบรรทัดใหม่ได้ ห้ามตัดรายละเอียดสำคัญจนอ่านไม่ได้
- ปุ่มมีพื้นที่กดอย่างน้อย 44px และมีโฟกัสคีย์บอร์ดที่มองเห็นได้
- ช่องกรอกต้องมี label ที่สัมพันธ์กัน ปุ่มเลือกโหมดต้องสื่อสถานะด้วย `aria-pressed` หรือรูปแบบ ARIA ที่เหมาะสม
- หลีกเลี่ยงการเคลื่อนไหวที่ไม่จำเป็น และรองรับ `prefers-reduced-motion` เมื่อเพิ่ม animation หรือ transition

## คีย์แพดกลาง

- เริ่มต้นแบบซ่อนเมื่อเปิดหน้าหรือเปลี่ยนเครื่องมือ
- เปิดเมื่อแตะหรือโฟกัสช่องที่เชื่อมกับคีย์แพดกลาง ผ่าน helper และ `data-shared-field` ที่มีอยู่
- แตะพื้นที่อื่นหรือกด Escape แล้วต้องซ่อน
- ระหว่างกดตัวเลขหรือปุ่มช่องก่อนหน้า/ถัดไป คีย์แพดต้องไม่หุบ
- การคำนวณหรือ render ใหม่ต้องไม่บังคับเปิดคีย์แพดที่ผู้ใช้ซ่อนไว้ และต้องไม่ทำตำแหน่งพิมพ์ของช่องกลางหาย
- ช่อง native ที่ไม่ได้เชื่อมกับคีย์แพดกลางต้องไม่เปิดคีย์แพดไปแก้ค่าของช่องอื่น
- ห้ามสร้างคีย์แพดอีกชุดหรือผูก event ซ้ำในแต่ละ renderer

## โครงสร้างและการตรวจงาน

- แก้ source ใน `src/` แล้วสร้าง `src/bundle.js` ผ่าน build script ห้ามแก้ bundle โดยตรง
- เมื่อแก้ asset ที่ service worker cache ไว้ ให้เพิ่มเวอร์ชัน cache ใน `sw.js` ตามความเหมาะสมก่อนส่งงาน
- งานแก้ดีไซน์ให้คงสูตรคำนวณและข้อมูลเดิม เว้นแต่ผู้ใช้สั่งแก้หรือพบข้อผิดพลาดที่จำเป็นต้องจัดการ ให้รายงานการเปลี่ยนพฤติกรรมเพิ่มเติมอย่างชัดเจน
- ตรวจภาพจริงทุกโหมดของเครื่องมือในทั้ง 5 ธีม: Airbnb, Classic, Dark Luxe, Together และ Ferrari ทั้งบนมือถือ 320px และเดสก์ท็อป
- ตรวจช่องกรอก ผลลัพธ์ ตัวเลขยาว ปุ่ม โฟกัส และคีย์แพด รวมถึงการส่งค่าระหว่างโหมดถ้ามี
- งานแก้โค้ดให้รันจากราก repository:

  ```sh
  node calculator_AIO/scripts/build.cjs
  node --test calculator_AIO/tests/correctness.test.cjs
  git diff --check
  ```

- งานเอกสารอย่างเดียวไม่ต้อง build หรือทดสอบสูตร ให้ตรวจ diff ตามความเหมาะสม
- รายงานเฉพาะสิ่งที่ตรวจจริง ระบุสิ่งที่ยังไม่ได้ตรวจหรือข้อจำกัด ห้ามอ้างว่าทดสอบผ่านโดยไม่ได้รัน
- เมื่อทำงานเสร็จ ให้สรุปสิ่งที่เปลี่ยน ผลตรวจ และสถานะ commit/push ไม่ต้อง commit หรือ push จนกว่าผู้ใช้จะสั่ง
