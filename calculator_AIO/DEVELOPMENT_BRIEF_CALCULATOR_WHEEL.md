# สรุปแนวทางพัฒนาเครื่องคิดเลขและตัวเลือกหน่วย

วันที่ 29 ตุลาคม 2026 · เอกสารสรุปการสนทนาเพื่อส่งต่อทีมพัฒนา

เอกสารนี้เป็น **แนวทางที่เสนอจากการสนทนา** ยังไม่ใช่งานที่พัฒนาเสร็จ และรายละเอียดที่ระบุว่า “เสนอ” สามารถปรับร่วมกับทีมก่อนเริ่มได้ ให้ใช้ `AGENTS.md` ในโฟลเดอร์นี้เป็นกติกาหลักด้านธีม การเข้าถึง และการตรวจงาน

## 1. เครื่องคิดเลขวิทยาศาสตร์

### แนวทางที่แนะนำ

เพิ่มโหมด **ทั่วไป / วิทยาศาสตร์** ในทูลเครื่องคิดเลขเดิม (`calc`) แทนการเพิ่มทูลใหม่ ผู้ใช้จึงใช้หน้าจอสมการ ผลลัพธ์ และประวัติร่วมกันได้ โดยสลับโหมดแล้วค่าที่กำลังคำนวณไม่หาย

โหมดทั่วไปคงการใช้งานเดิม โหมดวิทยาศาสตร์เพิ่มแผงฟังก์ชันเหนือแป้นตัวเลข ภาพอ้างอิงเป็นตัวอย่างด้านความสามารถและการจัดกลุ่มปุ่ม ไม่จำเป็นต้องคัดลอกสีหรือรูปร่างจากภาพ ให้ใช้ธีมกลางของแอป

### ขอบเขตรอบแรกที่เสนอ

- ปุ่มเลือกโหมดทั่วไป / วิทยาศาสตร์ และตัวเลือก **DEG / RAD** ที่เห็นสถานะชัด
- `sin`, `cos`, `tan` และฟังก์ชันผกผัน; `log`, `ln`; ยกกำลังและราก; `π`, `e`, `n!`, `1/x`, `Ans` และการป้อน/แสดงเลขแบบวิทยาศาสตร์
- บนมือถือเสนอแผงฟังก์ชัน 4 คอลัมน์ พร้อมปุ่ม `2nd` สำหรับฟังก์ชันรอง โดยให้พื้นที่กดอย่างน้อย 44px
- หน่วยความจำและฟังก์ชันไฮเพอร์โบลิกเป็นงานต่อยอด ไม่ใช่ข้อกำหนดรอบแรก

### งานเทคนิคและการยอมรับ

- ตรวจ `renderStandardCalcTool` ใน `src/tools/special.js`: ตัวประเมินเดิมอยู่ภายใน renderer และรองรับเลขกับเครื่องหมายพื้นฐาน จึงต้องแยกตัวประมวลผลสมการและออกแบบ parser ที่รองรับฟังก์ชันเพิ่มเติมอย่างปลอดภัย
- กำหนดลำดับการคำนวณ วงเล็บ การเปลี่ยนเครื่องหมาย `Ans` และพฤติกรรม `2nd` ให้ชัดก่อนลงมือ พร้อมแสดงข้อผิดพลาดเมื่ออินพุตไม่สมบูรณ์หรืออยู่นอกขอบเขตของฟังก์ชัน
- ตรวจความถูกต้องของ DEG/RAD เช่น `sin(90°) = 1` และ `sin(π/2 rad) = 1` รวมถึงค่าขอบเขต การหารด้วยศูนย์ แฟกทอเรียลและเลขยาว
- ตรวจว่าการสลับโหมดเก็บสมการ ผลลัพธ์ และประวัติได้ รวมทั้งปุ่มทั่วไป คีย์บอร์ด การคัดลอก และพฤติกรรมเดิมยังใช้ได้

## 2. ตัวเลือกหน่วยแบบวงล้อ

### ประสบการณ์ที่เสนอ

สร้างคอมโพเนนต์ Wheel Picker ที่ใช้ซ้ำได้ โดยวงล้อหน่วยต้นทางและปลายทางเลื่อนแยกกัน รายการที่อยู่ตรงแถบกลางคือหน่วยที่เลือกและคำนวณผลทันที ผู้ใช้แตะรายการเพื่อเลือกได้ และมีปุ่มสลับต้นทาง ↔ ปลายทาง

- เลือกหมวดหน่วยก่อน เช่น ความยาว น้ำหนัก และพื้นที่ เพื่อให้เลือกได้เฉพาะหน่วยในหมวดเดียวกัน
- บนมือถือเสนอให้เห็นประมาณ 3–5 รายการต่อคอลัมน์ เพื่อให้เหลือพื้นที่แสดงค่าที่กรอกและผลลัพธ์
- ใช้สีไฮไลต์และส่วนประกอบตามธีมกลาง; ช่องตัวเลขที่เชื่อมคีย์แพดกลางยังใช้พฤติกรรมเปิด/ซ่อนตาม `AGENTS.md`
- รองรับการแตะ คีย์บอร์ด ชื่อและสถานะสำหรับเทคโนโลยีช่วยอ่าน รวมถึงทางเลือกที่ใช้งานได้เมื่อไม่สะดวกเลื่อนวงล้อ
- ใช้สูตร หน่วย และข้อมูลเดิมของแต่ละทูลเป็นฐาน การเปลี่ยนหน้าตาต้องไม่เปลี่ยนผลคำนวณโดยไม่ตั้งใจ

### ลำดับการนำไปใช้

| ลำดับ | ทูล | แนวทาง |
| --- | --- | --- |
| 1 | แปลงหน่วย (`unit`) | เริ่มด้วยวงล้อสองฝั่งสำหรับหน่วยตั้งต้นและปลายทาง |
| 2 | แปลงสกุลเงิน (`currency`) | ใช้วงล้อสองฝั่ง และเพิ่มการค้นหาเพราะรายการสกุลเงินยาว; คงแหล่งข้อมูลและสถานะอัตราแลกเปลี่ยนเดิม |
| 3 | ต้นทุนอาหาร & สูตร (`food_costing`) | ประยุกต์เลือกหน่วยที่ซื้อและหน่วยที่ใช้ โดยเปิดตัวเลือกเฉพาะรายการที่กำลังแก้ |
| 4 | ราคาต่อหน่วย (`unit_price`) | พิจารณาใช้วงล้อฝั่งเดียวสำหรับแต่ละสินค้า โดยรักษาตารางเปรียบเทียบให้กระชับ |

ต้นทุนต่อพื้นที่ (`area_cost`) และประสิทธิภาพเชื้อเพลิง (`fuel_eff`) ยังไม่มีตัวเลือกต้นทาง–ปลายทางแบบเดียวกันในหน้าปัจจุบัน จึงยังไม่รวมในขอบเขตรอบแรก

### งานเทคนิคและการยอมรับ

- ออกแบบคอมโพเนนต์ให้รองรับการเลือกหนึ่งฝั่งและสองฝั่ง แยก state ของแต่ละฝั่ง และนำไปใช้ซ้ำโดยไม่ผูกสูตรเข้ากับ UI
- ตรวจการเลื่อนหยุดตรงรายการ การแตะเลือก ปุ่มสลับหน่วย การเปลี่ยนหมวด การเลือกหน่วยเดียวกัน และความต่อเนื่องของค่าที่กรอก
- เปรียบเทียบผลกับสูตรเดิม โดยเฉพาะหน่วยที่ไม่ได้แปลงด้วยตัวคูณอย่างเดียว เช่น อุณหภูมิ และตรวจกรณีไม่มีหรือโหลดอัตราแลกเปลี่ยนไม่สำเร็จตามพฤติกรรมเดิม
- ตรวจรายการยาว ชื่อหน่วยยาว จอ 320px และเดสก์ท็อป รวมถึงโฟกัสและการใช้งานโดยไม่ใช้เมาส์

## 3. การทำงานพร้อมกันของ Codex และ Gemini

ให้แต่ละฝ่ายทำงานใน **Git worktree และ branch แยกกัน** จากฐาน commit ที่ตกลงร่วมกัน ตัวอย่างชื่อ branch:

| งาน | Branch ตัวอย่าง |
| --- | --- |
| เครื่องคิดเลขวิทยาศาสตร์ | `feature/scientific-calculator` |
| วงล้อเลือกหน่วย | `feature/unit-wheel-picker` |

ไฟล์ที่อาจชนกัน ได้แก่ `index.html`, `src/catalog.js`, `src/bundle.js`, `sw.js` และโมดูลส่วนกลางด้านประวัติ คัดลอก และ PDF โดยเฉพาะ `src/bundle.js` เป็นไฟล์ที่สร้างจาก build ห้ามแก้ด้วยมือ

รวมงานทีละ branch ตรวจและแก้ conflict โดยรักษางานทั้งสองฝ่าย จากนั้น build bundle จาก source ที่รวมแล้ว ตรวจ service worker cache และรันชุดทดสอบอีกครั้ง หากจำเป็นต้องทำใน checkout เดียวกัน ให้ตกลงผู้รับผิดชอบไฟล์กลางและ build เพียงคนเดียว

## 4. ตรวจงานก่อนส่ง

ทำตาม `AGENTS.md` รวมถึงตรวจทั้ง 5 ธีม (Airbnb, Classic, Dark Luxe, Together, Ferrari), ทุกโหมดที่เปลี่ยน, มือถือ 320px และเดสก์ท็อป ตรวจข้อความยาว คอนทราสต์ ขนาดปุ่ม โฟกัส และคีย์แพด แล้วรันจากราก repository:

```sh
node calculator_AIO/scripts/build.cjs
node --test calculator_AIO/tests/correctness.test.cjs
git diff --check
```

เพิ่มการทดสอบที่ตรวจผลคำนวณและกรณีขอบเขตที่สำคัญของงานใหม่ สรุปเฉพาะสิ่งที่ตรวจจริงและระบุข้อจำกัดก่อนส่งต่อทีม
